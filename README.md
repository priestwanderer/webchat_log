# 弦 · 正式服执行日志

一个在本机运行的中文日志监控服务。通过已有 SSH 身份只读访问正式服，将执行记录保存在本地 SQLite，并在网页持续展示。

## 启动

需要 Python 3.11 或更新版本，以及可用的 OpenSSH。服务运行本身没有第三方 Python 依赖。

```bash
cd E:/Code/webchat_log
python app.py
```

也可以双击 `启动服务.cmd`。浏览器打开 `http://127.0.0.1:8765/`。

保持启动窗口运行即可持续采集；关闭窗口或按 Ctrl+C 停止。当前版本没有安装开机自启，也没有在正式服部署程序。启动前应已能以密钥或 SSH agent 无交互执行：

```bash
ssh -o BatchMode=yes -o StrictHostKeyChecking=yes root@38.147.163.155 hostname
```

首次建立服务器信任应人工核对主机指纹。程序不会关闭主机校验、保存密码或修改 SSH 配置。

## 功能

- 正式服账号目录、账号/邮箱搜索、按账号查看记录。
- 全部日志和错误日志切换，支持来源、状态、时间和关键词筛选。
- 请求编号、模型、错误详情、工具执行输出、观测到的状态历史。
- 网页通过服务端事件流刷新；暂停刷新只暂停页面，后台采集继续。
- 中文界面、深浅主题、窄屏布局。
- 断点持久化、分页补采、失败重试、来源级健康状态。

## 数据位置

- `data/webchat.sqlite3`：账号目录、记录、状态历史和采集断点。
- `data/webchat.sqlite3-wal` / `-shm`：SQLite 运行期间辅助文件。
- `data/collector.log`：采集服务自身日志，5 MB 轮转，保留 3 个备份。

业务记录不会自动过期删除。备份 SQLite 时应先停止服务再复制数据库，或使用 SQLite 在线备份接口。不要只在运行期间拷贝主文件而遗漏尚未落盘的 WAL。`data/` 和本地配置被 Git 忽略。

## 正式服访问与采集范围

默认目标为 `root@38.147.163.155`；数据库容器 `migration-replica-postgres-production`，端口 `55432`。所有查询使用 `BEGIN READ ONLY`，设置 8 秒语句超时、1 秒锁等待超时，不写入正式服文件、不修改配置、不安装程序。

| 页面来源 | 正式服数据表 | 范围 |
|---|---|---|
| 聊天请求 | sub2api.webchat_response_requests | 所有账号的 webchat 请求及错误 |
| 音频转写 | sub2api.webchat_audio_transcription_requests | 转写状态与错误 |
| 关联网关错误 | sub2api.ops_error_logs | 路由属于 webchat，或请求编号可与 webchat 请求关联的错误 |
| 消息执行 | openwebui.chat_message | 助手消息状态和错误，不采集聊天正文 |
| 工具执行 | openwebui.sub2api_managed_sandbox_command | 工具状态、结果和日志 |

同一执行可能同时有请求、消息和网关记录，页面按来源分别展示，记录总数不等于唯一执行次数。工具日志最多截取 24,000 字符，结果最多截取 16,000 字符，详情会标注截取。

账号归属以正式服用户编号为主；Open WebUI 消息及工具记录仅在现存会话映射指向唯一正式服账号时归属。存在多个映射或无法关联时标为未归属，不选取最新账号。该方式无法证明已被源系统删除的历史会话映射，若需要事件级绝对归属，须由源服务保存事件所属账号。

## 实时性和完整性边界

默认每轮采集结束后等待 10 秒，实际更新延迟还包含 SSH 和查询耗时。首轮补采最近 24 小时内发生更新的记录，因此可能包含更早创建、最近更新的请求。后续从断点继续，并保留 120 秒重叠窗口进行去重。

这是基于现有数据库的只读轮询监控，不是全量请求体录制或逐步骤链路追踪。不能保证还原两次采集之间的中间状态；正式服未保存的失败、浏览器本地错误、无法关联账号的 Nginx 请求不在本服务范围内。断线期间若源记录被删除，则无法补回；超过重叠窗口的延迟提交也可能需要更大重叠窗口或人工补采。页面明确展示连接失败和补采状态。

错误筛选包含失败/错误/超时状态或存在错误字段的记录。取消和待结算不自动视为失败。历史时间线表示本服务实际观测时刻，不冒充正式服完整执行时间线。

服务只监听本机回环地址，并校验 Host 和 Origin。不要未经鉴权改为公网监听。账号、邮箱和错误详情属于业务数据，请保管好本地数据库；密钥、会话令牌不在采集字段中，常见凭证模式会在持久化前脱敏。

## 可选本地配置

复制 `config.example.json` 为 `config.json` 后调整。`batch_size` 会统一限制在 1–2000，SQL 条数和分页判断使用相同值。此配置只影响本地采集程序，不修改正式服。`initial_hours` 仅在第一次创建数据库时生效，已有断点优先；更改它不会自动重新导入历史。

## 验证

`tests/`、浏览器测试依赖清单及测试产物仅在本地保留，不纳入生产仓库。下列测试命令供包含这些本地文件的开发目录使用；从仓库新检出的生产目录无需执行或安装测试依赖。

```bash
python -m unittest discover -s tests -v
node --check static/app.js
python app.py --once
```

`--once` 会采集并保存一轮真实正式服数据。浏览器测试优先使用已安装的 Microsoft Edge；没有 Edge 时先运行 `npx playwright install chromium`。测试时保持服务运行，安装开发依赖后执行：

```bash
npm install
node tests/browser.cjs
```
